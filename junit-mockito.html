🧪 JUnit e Mockito

Como testar o código Java.

1. O que são testes unitários?

Testam uma parte pequena do código (como um método ou classe), de preferência isolada.

@Test

void TestABC_When_Then() {
    //Given
    //When
    //Then
    //asserts

}

2. O que é JUnit?

JUnit é uma ferramenta para criar e executar testes automatizados em Java.

@Test

void deveSomarDoisNumeros() {

    int resultado = 2 + 3;

    assertEquals(5, resultado);

}

3. Annotations importantes

  • @Test: identifica um método de teste.
  • @BeforeEach: executa antes de cada teste.
  • @AfterEach: executa depois de cada teste.
  • @BeforeAll: executa uma vez antes dos testes da classe, normalmente deve ser static.
  • @AfterAll: executa uma vez depois dos testes da classe, normalmente deve ser static.
  • @DisplayName: define um nome legível para o teste.
  • @ParameterizedTest: executa um teste com diferentes parâmetros.

4. Assertions

Verificam se o resultado obtido corresponde ao esperado.

assertEquals(10, resultado);

assertTrue(idade >= 18);

assertNotNull(cliente);

4. O que é Mockito?

Mockito permite criar objetos simulados para testar uma classe sem depender de serviços reais.

  • @Mock: cria um objeto simulado.
  • @InjectMocks: cria o objeto testado e injeta os mocks compatíveis.
  • when(): define o comportamento esperado.
  • thenReturn(): define o valor que será retornado.
  • verify(): verifica se uma interação aconteceu.

5. Exemplo com Mockito

when(servico.buscarNome())

    .thenReturn("Amanda");

String nome = servico.buscarNome();

assertEquals("Amanda", nome);

verify(servico).buscarNome();

O exemplo pressupõe que o mock e os imports já estejam configurados.

6. Conceitos importantes

  • Mock: objeto simulado.
  • Stub: fornece respostas previamente configuradas.
  • SUT (System Under Test): objeto que está sendo testado.
  • TDD: desenvolver guiado por testes.
  • BDD: descrever comportamentos esperados.
  • JaCoCo: mede a cobertura de código pelos testes.
