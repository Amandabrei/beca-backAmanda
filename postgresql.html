🐘 PostgreSQL

Do ambiente WSL e comandos SQL aos índices, transações, desempenho e programação procedural.

1. O que é PostgreSQL?

PostgreSQL é um SGBD (Sistema Gerenciador de Banco de Dados) relacional e objeto-relacional, open source. Ele armazena, organiza e consulta dados usando SQL.

  • Banco de dados: conjunto organizado de dados.
  • SGBD: software que administra bancos, usuários e consultas.
  • Schema: espaço lógico que organiza objetos dentro de um banco.
  • SQL: linguagem usada para definir estruturas, consultar e manipular dados.

2. Cliente, servidor e conexão

  • Cliente: ferramenta que envia comandos, como psql, DBeaver ou pgAdmin.
  • Servidor: processo PostgreSQL que recebe conexões e administra os dados.
  • Processo de conexão: normalmente, o servidor cria um backend dedicado para cada sessão.
  • Processos internos: checkpointer, background writer, WAL writer, autovacuum e outros.
  • WAL: registra alterações antes da gravação definitiva das páginas de dados.

3. PostgreSQL no WSL (Ubuntu)

Instalar e iniciar o serviço:

sudo apt update
sudo apt install postgresql postgresql-contrib
psql --version
sudo service postgresql status
sudo service postgresql start
sudo -u postgres psql

Comandos dentro do psql:

\l                 -- listar bancos
\c nome_banco      -- conectar a um banco
\dt                -- listar tabelas
\d nome_tabela     -- visualizar estrutura
\dn                -- listar schemas
\du                -- listar usuários/roles
\q                 -- sair

Consultas úteis:

SELECT version();
SELECT current_database(), current_user;
SHOW port;
SELECT pg_database_size(current_database());

Atenção: se você tiver PostgreSQL no WSL e em um container, confira a porta e a instância à qual está conectada.

4. Categorias de comandos SQL

  • DDL: CREATE, ALTER, DROP, TRUNCATE.
  • DML: INSERT, UPDATE, DELETE, MERGE.
  • DQL: SELECT — classificação didática de consulta.
  • DCL: GRANT, REVOKE.
  • TCL: BEGIN, COMMIT, ROLLBACK, SAVEPOINT.
CREATE TABLE cliente (
  id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  nome text NOT NULL
);

INSERT INTO cliente (nome) VALUES ('Ana');

SELECT * FROM cliente;

UPDATE cliente
SET nome = 'Ana Silva'
WHERE id = 1;

DELETE FROM cliente WHERE id = 1;

5. Tabelas, tipos e comandos

CREATE TABLE produto (
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  nome varchar(100) NOT NULL,
  preco numeric(10,2) CHECK (preco >= 0),
  criado_em timestamptz DEFAULT now()
);

ALTER TABLE produto ADD COLUMN ativo boolean DEFAULT true;

ALTER TABLE produto RENAME COLUMN nome TO descricao;

TRUNCATE TABLE produto;

DROP TABLE produto;
  • Tipos comuns: integer, bigint, numeric, text, varchar, boolean, date, timestamp, timestamptz, uuid e jsonb.
  • IDENTITY: gera valores automaticamente.
  • PRIMARY KEY: identifica cada registro.
  • FOREIGN KEY: estabelece relacionamento entre tabelas.

6. SELECT, filtros e LIKE

SELECT nome, preco
FROM produto
WHERE preco BETWEEN 10 AND 100
ORDER BY preco DESC
LIMIT 10;

SELECT * FROM cliente
WHERE nome LIKE 'An%';

SELECT * FROM cliente
WHERE nome ILIKE '%silva%';
  • LIKE: procura padrões; % representa vários caracteres.
  • _: representa exatamente um caractere.
  • ILIKE: pesquisa sem diferenciar maiúsculas e minúsculas.
  • BETWEEN: verifica um intervalo inclusivo.
  • IN: compara com uma lista de valores.
  • IS NULL: verifica se o valor é nulo.
  • CASE: expressão condicional.
  • COALESCE: retorna o primeiro valor não nulo.
  • NULLIF: retorna NULL quando os valores comparados são iguais.

Revisar também INNER JOIN, LEFT JOIN, RIGHT JOIN, FULL JOIN e CROSS JOIN.

7. Views e comandos

View é uma consulta salva que pode ser utilizada como uma tabela lógica. Uma view comum não armazena os resultados. 

CREATE VIEW vw_produtos_ativos AS
SELECT id, nome, preco
FROM produto
WHERE ativo = true;

SELECT * FROM vw_produtos_ativos;

CREATE OR REPLACE VIEW vw_produtos_ativos AS
SELECT id, nome, preco
FROM produto
WHERE ativo = true;

DROP VIEW vw_produtos_ativos;

Materialized View: armazena o resultado da consulta.

CREATE MATERIALIZED VIEW mv_resumo AS
SELECT ...;

REFRESH MATERIALIZED VIEW mv_resumo;

DROP MATERIALIZED VIEW mv_resumo;

8. Restrições (constraints)

  • PRIMARY KEY: identifica unicamente uma linha.
  • FOREIGN KEY: garante relacionamento válido.
  • UNIQUE: impede duplicidade.
  • NOT NULL: exige um valor.
  • CHECK: verifica uma condição.
  • DEFAULT: define um valor padrão.
ALTER TABLE produto
ADD CONSTRAINT ck_preco CHECK (preco >= 0);

ALTER TABLE produto
ADD CONSTRAINT uq_nome UNIQUE (nome);

ALTER TABLE pedido
ADD CONSTRAINT fk_cliente
FOREIGN KEY (cliente_id) REFERENCES cliente(id);

ALTER TABLE produto
DROP CONSTRAINT ck_preco;

Também revise DEFERRABLE, INITIALLY DEFERRED, NOT VALID e VALIDATE CONSTRAINT.

9. Índices e desempenho

Índices podem acelerar consultas, mas ocupam espaço e aumentam o custo de INSERT, UPDATE e DELETE. 

CREATE INDEX idx_produto_preco
ON produto(preco);

CREATE UNIQUE INDEX idx_cliente_email
ON cliente(email);

CREATE INDEX idx_pedido_cliente_data
ON pedido(cliente_id, criado_em);

CREATE INDEX idx_produto_lower_nome
ON produto (lower(nome));

CREATE INDEX idx_produto_ativo
ON produto(id)
WHERE ativo = true;

DROP INDEX idx_produto_preco;

EXPLAIN
SELECT * FROM produto WHERE preco > 50;

EXPLAIN (ANALYZE, BUFFERS)
SELECT * FROM produto WHERE preco > 50;
  • B-tree: igualdade, intervalos e ordenação.
  • GIN: útil para certos arrays, JSONB e busca textual.
  • GiST e SP-GiST: estruturas para tipos e operadores específicos.
  • BRIN: útil para grandes tabelas com dados correlacionados à ordem física.
  • Índice composto: índice com mais de uma coluna; a ordem importa.
  • Índice parcial: indexa somente as linhas que atendem a uma condição.
  • EXPLAIN: mostra o plano estimado.
  • EXPLAIN ANALYZE: executa a consulta e mostra informações reais.

10. Classes de operadores e agregações

Classes de operadores definem como os tipos de dados e operadores são utilizados por métodos de índice.

Operadores comuns:

=   <>   <   >   <=   >=
AND   OR   NOT
LIKE   ILIKE
IN   BETWEEN   IS NULL

Funções de agregação:

SELECT COUNT(*) FROM pedido;

SELECT
  cliente_id,
  SUM(total),
  AVG(total),
  MIN(total),
  MAX(total)
FROM pedido
GROUP BY cliente_id
HAVING COUNT(*) > 1;

SELECT string_agg(nome, ', ' ORDER BY nome)
FROM cliente;

SELECT array_agg(id) FROM produto;
  • COUNT: conta linhas/valores.
  • SUM: soma.
  • AVG: calcula média.
  • MIN / MAX: menor e maior valor.
  • GROUP BY: agrupa registros.
  • HAVING: filtra grupos após a agregação.

11. Funções SQL e PL/pgSQL

Função pode retornar um valor ou conjunto de linhas. PL/pgSQL permite declarar variáveis, usar condições, laços e tratamento de exceções. 

CREATE OR REPLACE FUNCTION somar(a integer, b integer)
RETURNS integer
LANGUAGE plpgsql
AS $$
BEGIN
  RETURN a + b;
END;
$$;

SELECT somar(2, 3);

DROP FUNCTION somar(integer, integer);
  • DECLARE: declara variáveis.
  • BEGIN / END: delimitam o bloco.
  • IF / ELSIF / ELSE: condições.
  • LOOP / WHILE / FOR: estruturas de repetição.
  • RETURN: retorna resultado.
  • EXCEPTION: trata erros.
  • RAISE NOTICE: exibe mensagens.
  • %TYPE: utiliza o tipo de uma coluna ou variável.
  • %ROWTYPE: representa a estrutura de uma linha.
  • RECORD: registro cuja estrutura pode variar.

12. Procedures, CALL e DROP PROCEDURE

Procedure é executada com CALL. Diferentemente de uma função, não é utilizada diretamente como expressão em SELECT. 

CREATE OR REPLACE PROCEDURE reajustar_precos(
  p_percentual numeric
)
LANGUAGE plpgsql
AS $$
BEGIN
  UPDATE produto
  SET preco = preco * (1 + p_percentual / 100);
END;
$$;

CALL reajustar_precos(5);

DROP PROCEDURE reajustar_precos(numeric);

Revise parâmetros IN, OUT e INOUT e as diferenças entre FUNCTION, PROCEDURE, SELECT e CALL.

13. Cursores: DECLARE, OPEN, FETCH e CLOSE

Cursor permite percorrer os resultados de uma consulta de forma incremental. 

BEGIN;

DECLARE c CURSOR FOR
SELECT id, nome FROM produto;

FETCH NEXT FROM c;
FETCH FORWARD 5 FROM c;

MOVE FORWARD 2 FROM c;

CLOSE c;

COMMIT;
  • DECLARE: declara o cursor.
  • OPEN: abre um cursor em PL/pgSQL.
  • FETCH: busca linhas.
  • MOVE: desloca a posição do cursor.
  • CLOSE: fecha o cursor.

FETCH também pode usar PRIOR, FIRST, LAST, ABSOLUTE, RELATIVE, FORWARD e BACKWARD.

14. Tipos compostos e registros

Tipos compostos representam estruturas com vários campos.

CREATE TYPE endereco AS (
  rua text,
  cidade text,
  cep text
);

SELECT ROW(
  'Rua A',
  'Uberlândia',
  '38400-000'
)::endereco;

DROP TYPE endereco;

Toda tabela também cria um tipo composto correspondente à estrutura de suas linhas.

15. Triggers

Trigger executa uma função automaticamente quando ocorre determinado evento na tabela ou view. 

CREATE OR REPLACE FUNCTION registrar_alteracao()
RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
  RAISE NOTICE 'Operação: %', TG_OP;
  RETURN NEW;
END;
$$;

CREATE TRIGGER trg_produto
BEFORE INSERT OR UPDATE ON produto
FOR EACH ROW
EXECUTE FUNCTION registrar_alteracao();

DROP TRIGGER trg_produto ON produto;
  • BEFORE: antes do evento.
  • AFTER: depois do evento.
  • INSTEAD OF: substitui a operação, em casos suportados.
  • FOR EACH ROW: trigger por linha.
  • FOR EACH STATEMENT: trigger por comando.
  • NEW / OLD: registros novo e anterior, conforme o evento.
  • TG_OP: identifica a operação que disparou o trigger.

16. PL/Perl, SPI e PL/Python

  • PL/Perl: permite escrever funções PostgreSQL em Perl.
  • SPI: Server Programming Interface, interface que permite linguagens procedurais executar SQL dentro do servidor.
  • SPI em PL/Perl: funções da interface permitem executar comandos e tratar resultados SQL.
  • PL/Python: permite criar funções em Python no PostgreSQL.
  • plpython3u: linguagem não confiável; exige privilégios elevados.

PL/pgSQL é a linguagem procedural mais comum para lógica implementada dentro do PostgreSQL.

17. Transações, ACID e isolamento

BEGIN;

UPDATE conta
SET saldo = saldo - 100
WHERE id = 1;

SAVEPOINT etapa;

UPDATE conta
SET saldo = saldo + 100
WHERE id = 2;

ROLLBACK TO SAVEPOINT etapa;

COMMIT; -- ou ROLLBACK
  • Atomicidade: tudo ou nada.
  • Consistência: mantém as regras e a integridade.
  • Isolamento: controla a interação entre transações concorrentes.
  • Durabilidade: alterações confirmadas persistem.

Níveis de isolamento:

BEGIN;
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
-- comandos
COMMIT;
  • READ UNCOMMITTED
  • READ COMMITTED — padrão no PostgreSQL
  • REPEATABLE READ
  • SERIALIZABLE

No PostgreSQL, READ UNCOMMITTED se comporta como READ COMMITTED.

18. Locks, bloqueios e deadlocks

BEGIN;

SELECT *
FROM conta
WHERE id = 1
FOR UPDATE;

UPDATE conta
SET saldo = saldo - 50
WHERE id = 1;

COMMIT;

SELECT *
FROM conta
WHERE id = 1
FOR SHARE;
  • Locks de tabela e linha: protegem recursos durante operações concorrentes.
  • FOR UPDATE: bloqueia linhas para atualizações concorrentes incompatíveis.
  • FOR SHARE: bloqueia linhas contra modificações incompatíveis.
  • Deadlock: sessões aguardam recursos umas das outras; o PostgreSQL detecta e aborta uma transação.
  • Advisory locks: bloqueios definidos pela aplicação.

Monitoramento:

SELECT * FROM pg_stat_activity;
SELECT * FROM pg_locks;
SELECT pg_blocking_pids(pid)
FROM pg_stat_activity;

19. VACUUM, ANALYZE e manutenção

VACUUM produto;

VACUUM (VERBOSE, ANALYZE) produto;

ANALYZE produto;

VACUUM FULL produto;
  • VACUUM: permite reutilizar espaço de tuplas mortas.
  • ANALYZE: atualiza estatísticas usadas pelo otimizador.
  • Autovacuum: executa manutenção automática.
  • VACUUM FULL: reescreve a tabela, pode devolver espaço ao sistema operacional e exige lock forte.
  • MVCC: permite que transações trabalhem com versões de linhas.

20. Outros tópicos importantes

  • Sequences: CREATE SEQUENCE, nextval(), currval(), setval().
  • Permissões: CREATE ROLE, ALTER ROLE, GRANT, REVOKE.
  • Backup: pg_dump, pg_restore e psql.
  • Importação/exportação: COPY e \copy.
  • CTE: WITH e WITH RECURSIVE.
  • Window functions: OVER, PARTITION BY, ROW_NUMBER(), RANK(), LAG(), LEAD().
  • JSONB: armazenamento e operadores para JSON.
  • Particionamento: divisão de tabelas por faixa, lista ou hash.
  • Planos de consulta: Seq Scan, Index Scan, Bitmap Scan, Nested Loop e Hash Join.

21. Mapa rápido para memorizar

  • SELECT: consulta dados.
  • INSERT, UPDATE, DELETE: manipulam dados.
  • CREATE, ALTER, DROP: definem ou modificam estruturas.
  • VIEW: consulta salva; materialized view guarda resultados.
  • Índice: pode acelerar leitura, mas tem custo.
  • FUNCTION: chamada em SQL; PROCEDURE: executada com CALL.
  • TRIGGER: dispara uma função automaticamente.
  • BEGIN, COMMIT, ROLLBACK: controlam transações.
  • VACUUM: manutenção; ANALYZE: estatísticas.
  • EXPLAIN ANALYZE: examina execução real.
